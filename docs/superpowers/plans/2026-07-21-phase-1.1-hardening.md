# Phase 1.1 — Hardening Plan

Fixes the Critical + 6 Important findings from the staff roundtable review (Claude + Grok).
Source findings: `.superpowers/sdd/` review notes. No new features; resilience/correctness only.
**No tests this phase** (verify with `cargo clippy` + a regtest run). Money stays `Amount`.

## Tasks (execute in order; each ends `cargo clippy` clean + commit)

---

### H1 — RPC layer: timeout + reconnect + combined mempool info (`src/rpc.rs`)

Addresses findings #5 (cookie rotation → permanent auth failure), #6 (no RPC timeout), and folds in
the redundant `getmempoolinfo` (Minor #9).

- **Store reconnect state.** Keep the `RpcConfig` (clone) on the `Rpc` struct so the client can be
  rebuilt. Methods that hit the node take `&mut self` (the sync loop owns `Rpc` by value, so this is
  fine; `http` does not use `Rpc`).
- **Timeout-capable client.** Build the client through a timeout-capable transport instead of the bare
  `Client::new`. Reintroduce a `timeout: Duration` on `RpcConfig` **and** its CLI/env knob
  (`--rpc-timeout-secs` / `RPC_TIMEOUT_SECS`, default `30`) in `config.rs` — this time actually wired.
  Construct via `bitcoincore_rpc::jsonrpc` `simple_http` with `.timeout(cfg.timeout)`, resolving auth
  ourselves: `RpcAuth::Cookie(path)` → read the file, split on `:` into user/pass; `RpcAuth::UserPass`
  → use directly. Then `Client::from_jsonrpc(jsonrpc::Client::with_transport(transport))`.
  Factor this into a private `fn build_client(cfg: &RpcConfig) -> anyhow::Result<Client>`.
- **Reconnect on auth error.** Add a private helper that, on an RPC error whose JSON-RPC code indicates
  auth failure (or on a transport error), rebuilds the client once (re-reading the cookie) and retries
  the call. Keep it simple: a `fn with_reconnect<T>(&mut self, f: impl Fn(&Client) -> Result<T>)`-style
  wrapper, or an explicit retry in each method. One rebuild attempt per call is enough.
- **Combined mempool info.** Add `pub fn mempool_info(&mut self) -> anyhow::Result<MempoolInfo>` returning
  a small struct `{ loaded: bool, min_fee_sat_vb: f64 }` from ONE `get_mempool_info()` call. Remove the
  separate `mempool_loaded()` / `mempool_min_fee_sat_vb()` if now unused (or keep only what H2 calls).
- Keep `raw_mempool_txids`, `raw_mempool_verbose`, `tip_height`, `mempool_entry`, `network` (adjust to
  `&mut self` and route through the reconnect wrapper).

**Interfaces produced (H2 consumes):**
`Rpc::mempool_info(&mut self) -> Result<MempoolInfo{loaded: bool, min_fee_sat_vb: f64}>`;
`raw_mempool_txids(&mut self) -> Result<Vec<Txid>>`; `raw_mempool_verbose(&mut self) -> Result<Vec<(Txid, MempoolTx)>>`;
`tip_height(&mut self) -> Result<u64>`; `mempool_entry(&mut self, &Txid) -> Result<Option<MempoolTx>>`.

Verify against `cargo doc -p bitcoincore-rpc` that `Client::from_jsonrpc` and the `jsonrpc::simple_http`
builder + `.timeout` exist in the pinned version; adjust to the real API. `cargo clippy` clean; commit.

### H2 — Sync loop, state, and health rework (`src/sync.rs`, `src/mempool.rs`, `src/http.rs`)

Addresses #1 (health lies on error), #2 (batch discard / removals hostage to fetch), #3 (guard
self-disables, never bulk-loads), #4 (full clone → key-only). Folds in Minors #8 (poison idiom),
#12 (integer threshold), #14 (`last_sync_ok`).

- **`mempool.rs`:**
  - Add `last_sync_ok: Option<std::time::SystemTime>` to `MempoolState` (init `None`).
  - Change `compute_diff` to take the cache **key set**:
    `pub fn compute_diff(cache_keys: &HashSet<Txid>, node_txids: &HashSet<Txid>) -> Diff`.
  - Add a poison-tolerant helper used everywhere locks are taken:
    `pub fn write_state(state: &SharedState) -> RwLockWriteGuard<'_, MempoolState>` →
    `state.write().unwrap_or_else(|p| p.into_inner())`, and a `read_state` counterpart.
- **`sync.rs` steady-state loop** (rewrite):
  1. `sleep(poll_interval)`.
  2. `let info = rpc.mempool_info()?` — on error: `mark_stale(&state)` (set `caught_up=false`) + `continue`.
  3. `let node_txids: HashSet<Txid> = rpc.raw_mempool_txids()?` — on error: `mark_stale` + `continue`.
  4. Snapshot **keys only**: `let cache_keys = { let g = read_state(&state); (g.txs.len(), g.txs.keys().copied().collect::<HashSet<_>>()) };`
  5. **Resync decision** (replaces the old boolean guard, independent of prior `caught_up`):
     `if !info.loaded || (cache_len >= MASS_DROP_MIN_CACHE_SIZE && node_txids.len().saturating_mul(5) < cache_len) { bulk_resync(); continue; }`
     where `bulk_resync` calls `raw_mempool_verbose` and replaces `txs` wholesale, sets metadata,
     `caught_up=true`, `last_sync_ok=now` (on its own error: `mark_stale` + `continue`).
  6. `let diff = compute_diff(&cache_keys, &node_txids)`.
  7. **Apply removals immediately** (the txid list is authoritative): `write_state`, remove `diff.gone`.
  8. **Fetch adds best-effort**: for each `txid` in `diff.new`, `rpc.mempool_entry` → push `Ok(Some)`,
     skip `Ok(None)`; on `Err`, `warn!` and **skip that txid** (do NOT abort the batch, do NOT discard
     already-fetched). Insert whatever was fetched via `write_state`. (Missing ones reappear as `new`
     next tick.)
  9. Best-effort metadata: set `mempool_min_fee_sat_vb = info.min_fee_sat_vb`; `tip_height = rpc.tip_height()`
     if `Ok` (else leave prior).
  10. `caught_up = true; last_sync_ok = Some(now)`.
  - Delete `MASS_DROP_RATIO` (f64); keep `MASS_DROP_MIN_CACHE_SIZE`. Add `fn mark_stale(state)` that sets
    `caught_up=false` under `write_state`. Keep lock discipline: never hold a guard across an RPC call.
- **`http.rs`:** use `read_state`; add `last_sync_ok` to the `Health` response as unix seconds
  (`Option<u64>`), e.g. seconds since epoch, so operators can tell "never synced" vs "synced Ns ago".

`cargo clippy` clean; commit.

### H3 — Supervise the sync thread (`src/main.rs`)

Addresses #7 (unsupervised detached thread → panic = silent permanent freeze while `/health` may still
report ready).

- Capture the `JoinHandle` from `std::thread::spawn`. Since `sync::run` is an infinite loop, its only exit
  is a panic. Supervise it: spawn a small watcher (or `join` on a dedicated task) that, if the sync thread
  ends, logs an error and **terminates the process** (`std::process::exit(1)`) so a supervisor
  (systemd/docker) restarts it — a frozen-but-alive process that lies about health is worse than a clean exit.
- Keep everything else in `main` unchanged.

`cargo clippy` clean; commit.
